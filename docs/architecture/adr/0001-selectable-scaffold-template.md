# ADR-0001：模板采用选装式独立项目形态

> status: accepted · date: 2026-11-09 · owner: ZnLuAr

## 背景

工作目录下的项目以独立兄弟仓库为主（go-* 系列、Python 工具等），没有常驻 monorepo。用户主要语言是 Python，Go 用于工作。模板需要支持多语言，但多数项目实际只用一种语言。

## 决策

`template` 仓库作为**菜单 + 生成器**：

- `scaffold/<lang>/` 保存各语言种子（工具链配置、四层骨架、语言规则段）；
- `scripts/init.py --name --lang` 实例化出**单语言独立仓库**；
- 跨语言共享的部分（文档机制、AI 体系、通用规范、检查脚本）上提到模板根，实例化时统一携带。

对比过的备选：工作台 monorepo（apps/ + libs/ 常驻多语言）与固定槽位单仓（backend/frontend/native 写死）。两者都被否：前者为不存在的组件化产品付常驻复杂度，后者让用不到的槽位空转。

## 后果

**正面**

- 与既有兄弟仓库形态一致，实例化项目零模板包袱（不携带生成器）；
- 加语言 = 加一个 `scaffold/` 目录 + 一篇规范 + 冒烟用例，不改生成器。

**负面与代价**

- 单项目多语言暂不支持，需要时再演进组件化方案；
- 生成器成为必须测试维护的代码（由 `scripts/tests/` 冒烟覆盖）。
